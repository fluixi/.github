# Contributing to Fluixi

Thanks for taking the time to help. Bug reports, fixes, docs and examples are all welcome.

A repository with its own `CONTRIBUTING.md` follows that file; [core](https://github.com/fluixi/core/blob/alpha/CONTRIBUTING.md) has one. Everywhere else, this guide applies.

## Before you start

Fluixi is in alpha. For a large change or a new API, open an issue first so we can agree on the shape.

## Issues

Include a minimal reproduction: a [playground](https://playground.fluixi.com) link or a small repository, the package versions, and what you expected to happen.

## Pull requests

- Keep a pull request to one change.
- A bug fix comes with a test that fails without it.
- A change to a published package comes with a changeset (`pnpm changeset`) describing it from a user's point of view.
- Describe what changed and how you checked it. CI must pass before merging.
